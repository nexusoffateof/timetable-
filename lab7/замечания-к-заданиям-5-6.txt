КОРОТКО

Оба файла работают по методичке и считают результат правильно, пока
пользователь ведёт себя ожидаемо. Проблемы начинаются на краевых случаях.
Самая серьёзная — пункт 1: файл 5 полностью перестаёт работать, если нажать
«Дальше», не выбрав вариант ответа. Это воспроизводится с первой же попытки,
так что проверяющий наткнётся на неё почти наверняка.


1. ФАЙЛ 5: «ДАЛЬШЕ» БЕЗ ВЫБРАННОГО ВАРИАНТА ЛОМАЕТ ТЕСТ

Где: function call(), две первые строки.

    let kod = +form2.test.value;
    form2.test[kod-1].checked = false;

Если ни один переключатель не выбран, form2.test.value равно пустой строке.
Унарный плюс превращает её в 0, дальше идёт обращение form2.test[-1], это
undefined, и присваивание undefined.checked выбрасывает исключение:

    TypeError: Cannot set properties of undefined (setting 'checked')

Что видит пользователь: кнопка «Дальше» не делает ничего. Задание не
меняется, счётчик не растёт, тест стоит на первом вопросе. Ошибка видна
только в консоли (F12). Проверено в браузере.

Почему это важно: исключение происходит ДО строки ii++, поэтому состояние
теста не портится — но и не двигается. Выйти можно только перезагрузкой.

Как чинить (одна строка в начало тела call()):

    if (form2.test.value == "") return;

Тогда «Дальше» без ответа просто ничего не делает, без ошибки в консоли.

Вариант построже — сообщить пользователю:

    if (form2.test.value == "") {
      alert("Выберите вариант ответа");
      return;
    }


2. ФАЙЛ 6: «ДАЛЬШЕ» БЕЗ ОТВЕТА МОЛЧА ЗАСЧИТЫВАЕТ ОШИБКУ

Где: function call(), цикл for of.

Здесь исключения нет: если ничего не отмечено, kod остаётся пустой строкой,
сравнение с правильным ответом даёт false, и тест спокойно переходит к
следующему заданию. Формально не ошибка, но пользователь может пролистать
весь тест, ни разу ничего не выбрав, и получить 0 из 5 без единого
предупреждения.

Как чинить — та же проверка, но после цикла:

    if (kod == "") return;


3. ОБА ФАЙЛА: ПО ТЕКСТУ ВАРИАНТА ОТВЕТА НЕЛЬЗЯ ЩЁЛКНУТЬ

Где: раздел body, теги вариантов ответа.

    <p><input type="radio" name="test" value=1>
    <span id="r1"> </span></p>

Текст варианта лежит в теге span, который никак не связан с полем ввода.
Попасть можно только в сам кружок или квадратик — это примерно 13x13
пикселей. Проверено: щелчок по тексту варианта не выделяет его.

Как чинить — заменить span на label с привязкой к полю:

    <p><input type="radio" name="test" value=1 id="v1">
    <label id="r1" for="v1"> </label></p>

Тогда щелчок по тексту выделяет вариант. Идентификаторы r1..r4 сохраняются,
скрипт менять не надо — label тоже имеет свойство innerHTML.

Замечание: в образце формы из методички вариантов с label нет, так что это
улучшение, а не исправление ошибки.


4. ФАЙЛ 6: КОД ОТВЕТА СОБИРАЕТСЯ В ПОРЯДКЕ РАЗМЕТКИ, А НЕ НАЖАТИЙ

Где: цикл for (let elem of form2.test).

Цикл идёт по флажкам в порядке их записи в HTML, поэтому если отметить
сначала третий вариант, потом второй, код всё равно получится "23", а не
"32". Проверено.

Это не ошибка, а нужное поведение: правильные ответы в массиве записаны по
возрастанию ("12", "23", "34"), и собирать код в порядке нажатий было бы
неверно. Но на защите об этом стоит сказать самому — вопрос «а если выбрать
в другом порядке» задают часто.


5. ФАЙЛ 6: ТИП ПРАВИЛЬНОГО ОТВЕТА ОБЯЗАН БЫТЬ СТРОКОЙ

Где: шестой элемент каждого mas[i].

    "23"   — правильно
    23     — ловушка

Сравнение в call() нестрогое (==), поэтому числовой ответ 4 и строковый
код "4" совпадут, и одиночный правильный ответ сработает. А вот ответ 23
(число) и код "23" тоже совпадут, так что ошибку заметить трудно. Но если
правильный ответ начинается с нуля или содержит два одинаковых варианта,
числовая запись сломается. Методичка прямо требует строку — так и записано
во всех пяти заданиях.

Надёжнее заменить == на === в обоих файлах, тогда ловушка исчезает, но
тогда в файле 5 правильные ответы тоже обязаны стать строками.


6. ОБА ФАЙЛА: МАССИВ ЗАДАНИЙ НАЧИНАЕТСЯ С ИНДЕКСА 1

Где: mas[1] ... mas[5], при этом mas[0] не существует.

Сделано, чтобы номер задания ii совпадал с индексом массива. Побочный
эффект: mas.length равен 6, а не 5, и перебирать массив циклом for of
нельзя — первым придёт undefined. Поэтому число заданий хранится отдельно
в переменной nn, и её надо не забыть поменять, если заданий станет больше.


7. ОБА ФАЙЛА: ВИДИМОСТЬ ФОРМ ПОСЛЕ ПЕРВОГО ЗАПУСКА УПРАВЛЯЕТСЯ ТОЛЬКО
   СКРИПТОМ

Где: раздел style, правило #form2, #form3 { display: none; } и строки вида
form2.style.display="block".

Скрипт проставляет display через атрибут style прямо в теге, а такое
значение сильнее правила из раздела style. После первого нажатия «Старт»
правило #form2 больше ни на что не влияет: видимостью целиком распоряжаются
функции start(), call() и over(). Это работает, но означает, что вернуть
исходное состояние можно только кнопкой «Завершить» или перезагрузкой.


ЧТО ПРОВЕРЕНО И РАБОТАЕТ

- Подсчёт результата. Все пять верных ответов дают «5 из 5», частично
  верные — ровно столько, сколько совпало.
- Переходы форм: первая -> вторая -> третья -> первая.
- Сброс состояния: после «Завершить» и повторного «Старт» тест начинается
  с первого задания, счётчик обнулён, отметки с вариантов сняты.
- В файле 6 снятие отметок (elem.checked=false) происходит внутри цикла,
  поэтому следующее задание открывается с чистыми флажками.


ПОРЯДОК ИСПРАВЛЕНИЙ ПО ВАЖНОСТИ

2. Пункт 2 — желательно, по той же логике.
3. Пункт 3 — улучшение удобства, на оценку влиять не должно.
4. Пункты 4-7 — пояснения, менять ничего не требуется.
