# Включение: аккаунт, бот, напоминания

Пошагово, с указанием где нажимать. Порядок менять нельзя: каждый шаг
опирается на предыдущий.

Всего понадобится четыре вкладки: Supabase, Vercel, Telegram и GitHub.

---

## Шаг 1. Ключи Supabase

Откройте <https://supabase.com/dashboard>, выберите проект
**Timetable-for-work-time**.

Слева внизу шестерёнка **Project Settings** → в меню **API Keys**.
Нужны три значения, откройте блокнот и скопируйте их туда:

| Что | Где на странице |
|---|---|
| Project URL | раздел **Project URL**, вида `https://xxxx.supabase.co` |
| anon public | раздел **API keys**, строка `anon` `public` |
| service_role | там же, строка `service_role` — нажать **Reveal** |

**`service_role` никому не показывайте.** Он обходит все правила доступа
и видит базу целиком. В браузер он не попадёт: используется только сервером.

---

## Шаг 2. Настройки входа в Supabase

Слева **Authentication** → **Sign In / Providers** → карточка **Email**.

- **Confirm email** — если оставить включённым, после регистрации придёт
  письмо со ссылкой, и без неё войти нельзя. Для расписания «для себя»
  проще выключить: переключатель **Confirm email** → **Off** → **Save**.
- Если оставляете включённым: **Authentication** → **URL Configuration** →
  **Site URL** впишите адрес сайта (`https://ваш-проект.vercel.app`),
  иначе ссылка из письма приведёт на `localhost`.

## Шаг 3. Бот в Telegram

В Telegram найдите **@BotFather** → отправьте `/newbot`.

1. Он спросит имя — любое, например `Моё расписание`.
2. Потом username — должен заканчиваться на `bot`, например
   `moe_raspisanie_bot`. Если занят, попробуйте другой.
3. В ответ придёт строка вида `123456789:AAH...` — **это токен**.
   Скопируйте в блокнот.

Токен даёт полный контроль над ботом. В код его класть нельзя.

## Шаг 4. Два секрета

Придумайте две случайные строки. В терминале:

```bash
openssl rand -hex 16
openssl rand -hex 16
```

Первую назовём `TELEGRAM_WEBHOOK_SECRET`, вторую `CRON_SECRET`.
Запишите обе.

## Шаг 5. Переменные окружения в Vercel

<https://vercel.com/dashboard> → ваш проект → вкладка **Settings** сверху →
слева **Environment Variables**.

Для каждой строки таблицы: в поле **Key** имя, в **Value** значение,
галочки **Production**, **Preview**, **Development** — все три, затем **Save**.

| Key | Value |
|---|---|
| `VITE_SUPABASE_URL` | Project URL из шага 1 |
| `VITE_SUPABASE_ANON_KEY` | ключ `anon public` |
| `SUPABASE_URL` | тот же Project URL |
| `SUPABASE_ANON_KEY` | тот же `anon public` |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ `service_role` |
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | первая случайная строка |
| `CRON_SECRET` | вторая случайная строка |
| `VITE_TELEGRAM_BOT` | username бота **без** `@` |
| `ANTHROPIC_API_KEY` | необязательно, для чата-помощника |

Префикс `VITE_` — не украшение. Всё, что с ним, Vite подставляет прямо
в код страницы и видно любому посетителю. Поэтому `service_role`
и токен бота идут **без** него.

**Переменные применяются только при новой сборке.** Вкладка **Deployments** →
у верхней строки кнопка **⋯** справа → **Redeploy** → **Redeploy**.

Через минуту откройте сайт: появится экран входа. Зарегистрируйтесь —
почта и пароль от восьми символов. Если расписание уже было заполнено
в этом браузере, оно переедет в аккаунт само.

## Шаг 6. Вебхук бота

Один раз, из терминала. Подставьте свои значения:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d url=https://<ваш-домен>.vercel.app/api/telegram \
  -d secret_token=<TELEGRAM_WEBHOOK_SECRET>
```

Ответ должен содержать `"ok":true`. Проверить:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

В ответе должен быть ваш адрес и `"pending_update_count":0`.
Если там `"last_error_message"` — адрес или секрет не совпали.

## Шаг 7. Привязка Telegram

На сайте: шестерёнка **Настройки** справа сверху → вкладка **Напоминания** →
кнопка **Получить код привязки**.

Появится команда вида `/start K7M2QX`. Либо нажмите **Открыть бота
и привязать**, либо отправьте эту команду боту руками.

Бот ответит «Готово, аккаунт привязан». Проверьте: отправьте ему `/today` —
придёт расписание на сегодня.

Код живёт 10 минут и срабатывает один раз.

## Шаг 8. Запуск напоминаний по расписанию

**На бесплатном тарифе Vercel cron разрешён не чаще раза в сутки**, а деплой
с расписанием «каждые 5 минут» на Hobby не пройдёт вовсе. Поэтому рассылку
запускает GitHub Actions — бесплатно, минимум 5 минут.

Откройте <https://github.com/nexusoffateof/timetable-> → вкладка **Settings**
сверху → слева **Secrets and variables** → **Actions** → зелёная кнопка
**New repository secret**. Добавьте два, по одному:

| Name | Secret |
|---|---|
| `REMINDERS_URL` | `https://<ваш-домен>.vercel.app/api/reminders` |
| `CRON_SECRET` | та же вторая случайная строка, что в Vercel |

Проверка: вкладка **Actions** сверху → слева **Напоминания об уроках** →
справа **Run workflow** → **Run workflow**. Через полминуты обновите
страницу: у запуска должна быть зелёная галочка. Нажмите на него,
раскройте шаг — увидите `HTTP 200` и сводку вида
`{"найдено":0,"отправлено":0}`.

Дальше он будет запускаться сам каждые 5 минут.

<details>
<summary>Если у вас платный тариф Vercel</summary>

Создайте в корне репозитория `vercel.json` и удалите
`.github/workflows/reminders.yml`:

```json
{
  "crons": [{ "path": "/api/reminders", "schedule": "*/5 * * * *" }]
}
```

Vercel сам добавит заголовок с `CRON_SECRET`.
</details>

## Шаг 9. Проверка напоминания, не дожидаясь урока

Supabase → слева **SQL Editor** → **New query** → вставьте и нажмите **Run**:

```sql
-- Урок через 14 минут по вашему часовому поясу
insert into public.lesson_overrides
  (user_id, on_date, bell_id, subject_id, class_name, topic, starts_at, ends_at)
select p.id,
       (now() at time zone p.timezone)::date,
       b.id, s.id, '8А', 'Проверка напоминания',
       ((now() at time zone p.timezone) + interval '14 minutes')::time,
       ((now() at time zone p.timezone) + interval '59 minutes')::time
from public.profiles p
join public.bells b on b.user_id = p.id and b.position = 1
join public.subjects s on s.user_id = p.id
where p.id = (select user_id from public.telegram_links limit 1)
limit 1
on conflict (user_id, on_date, bell_id) do update
   set starts_at = excluded.starts_at, ends_at = excluded.ends_at, status = 'planned';

-- Что увидит рассылка прямо сейчас
select * from public.due_reminders(6);
```

Если вторая строка вернула запись — всё готово. Запустите workflow руками
(шаг 8), и напоминание придёт в Telegram.

Не забудьте потом убрать проверочный урок: на сайте правый клик по нему →
**Удалить урок**.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Сайт открывается без экрана входа | `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` не заданы или не было пересборки |
| «Не удалось получить код» | нет `SUPABASE_SERVICE_ROLE_KEY` или `SUPABASE_ANON_KEY` в Vercel |
| Бот молчит на любые команды | вебхук не установлен, либо `TELEGRAM_WEBHOOK_SECRET` в Vercel и в `setWebhook` разные |
| Бот отвечает «Код не найден» | код старше 10 минут или уже использован — возьмите новый |
| `/today` пуст, хотя расписание есть | вошли не тем аккаунтом, к которому привязан бот |
| Workflow зелёный, но `найдено: 0` | до ближайшего урока больше, чем упреждение; или напоминание уже отправлено — смотрите `reminder_log` |
| Напоминания приходят со сдвигом | часовой пояс в «Настройки → Общее» не ваш |

## Что закрыто в коде

**Часовые пояса.** Момент урока считает база: `now() at time zone
profiles.timezone` даёт настенные часы конкретного учителя, и уже в них
складываются дата и время урока. Проверено на случае, где сервер и учитель
находятся в разных календарных сутках.

**Дубли.** Сначала заявка, потом отправка: строка в `reminder_log`
вставляется до обращения к Telegram, поэтому параллельный запуск упирается
в конфликт первичного ключа. Сорвалась отправка — заявка снимается,
следующий запуск повторит.

**Заблокированный бот.** Telegram отвечает 403 — связь удаляется, заявка
остаётся: повторять бессмысленно.

**Устойчивость.** Каждая отправка в своём try/catch: недоступность одного
чата не отменяет рассылку остальным.

**Каникулы и отмены.** Отсекает `resolved_lessons()`.

**Изоляция.** Политики RLS: чужие строки не читаются и не пишутся, проверено
двумя пользователями на живой базе.
