Шаблоны из методички считают результат правильно, пока пользователь ведёт

Пункты 1-3 исправлены во всех трёх файлах: Буславский5.html,
Буславский6.html и Буславский7-02.html (последний собран из того же

=====================================================================
1. «ДАЛЬШЕ» БЕЗ ВЫБРАННОГО ВАРИАНТА ЛОМАЛ ТЕСТ   [ИСПРАВЛЕНО]
   Файл: Буславский5.html, function call()
=====================================================================

Было:

    function call() {
    let kod = +form2.test.value;
    form2.test[kod-1].checked = false;

Если ни один переключатель не выбран, form2.test.value равно пустой строке.
Унарный плюс превращает её в 0, дальше идёт обращение form2.test[-1], это
undefined, и присваивание undefined.checked выбрасывало исключение:

    TypeError: Cannot set properties of undefined (setting 'checked')

Что видел пользователь: кнопка «Дальше» не делала ничего. Задание не
менялось, счётчик не рос, тест стоял на первом вопросе. Ошибка была видна
только в консоли (F12), выйти можно было лишь перезагрузкой.

Исключение происходило до строки ii++, поэтому состояние теста не портилось
— но и не двигалось.

Стало (добавлена одна строка в начало тела функции):

    function call() {
    if (form2.test.value == "") return;
    let kod = +form2.test.value;
    form2.test[kod-1].checked = false;

Теперь «Дальше» без ответа просто ничего не делает, без ошибки в консоли.
Проверено: три нажатия подряд оставляют тест на первом задании, консоль
чистая.


=====================================================================
2. «ДАЛЬШЕ» БЕЗ ОТВЕТА МОЛЧА ЗАСЧИТЫВАЛ ОШИБКУ   [ИСПРАВЛЕНО]
   Файлы: Буславский6.html, Буславский7-02.html, function call()
=====================================================================

При множественном выборе исключения не было: если ничего не отмечено, kod
оставался пустой строкой, сравнение с правильным ответом давало false, и
тест спокойно переходил к следующему заданию. Формально не ошибка, но можно
было пролистать весь тест, ни разу ничего не выбрав, и получить 0 из 5 без
единого предупреждения.

Стало (проверка добавлена после цикла сбора кода):

    for (let elem of form2.test) {
      if (elem.checked) {
        kod=kod+elem.value;
        elem.checked=false;
      }
    }
    if (kod == "") return;
    if (mas[ii][5] == kod) rez++;

Важно, что проверка стоит именно после цикла, а не до: если ничего не
отмечено, цикл и так ничего не снимает, так что порядок безопасен.


=====================================================================
3. ПО ТЕКСТУ ВАРИАНТА ОТВЕТА НЕЛЬЗЯ БЫЛО ЩЁЛКНУТЬ   [ИСПРАВЛЕНО]
   Все три файла, раздел body
=====================================================================

Было:

    <p><input type="radio" name="test" value=1>
    <span id="r1"> </span></p>

Текст варианта лежал в теге span, никак не связанном с полем ввода. Попасть
можно было только в сам кружок или квадратик — примерно 13x13 пикселей.

Стало:

    <p><input type="radio" name="test" value=1 id="v1">
    <label id="r1" for="v1"> </label></p>

Атрибут for связывает подпись с полем по его идентификатору, поэтому щелчок
по тексту выделяет вариант. Идентификаторы r1..r4 сохранены, скрипт менять
не пришлось: у label, как и у span, есть свойство innerHTML.

Проверено: щелчок по тексту второго варианта отмечает именно его.

В образце формы из методички label нет, так что это улучшение удобства,
а не исправление ошибки по условию задания.


=====================================================================
ПУНКТЫ НИЖЕ — ПОЯСНЕНИЯ, ИСПРАВЛЕНИЙ НЕ ТРЕБУЮТ
=====================================================================

4. КОД ОТВЕТА СОБИРАЕТСЯ В ПОРЯДКЕ РАЗМЕТКИ, А НЕ НАЖАТИЙ
   Файлы 6 и 7-02, цикл for (let elem of form2.test)

Цикл идёт по флажкам в порядке их записи в HTML, поэтому если отметить
сначала третий вариант, потом второй, код всё равно получится "23", а не
"32".

Это нужное поведение: правильные ответы в массиве записаны по возрастанию
("12", "23", "34"), и собирать код в порядке нажатий было бы неверно.
Вопрос «а если выбрать в другом порядке» задают часто — ответ: результат не
изменится, порядок задаёт разметка.


5. ТИП ПРАВИЛЬНОГО ОТВЕТА ПРИ МНОЖЕСТВЕННОМ ВЫБОРЕ ОБЯЗАН БЫТЬ СТРОКОЙ
   Шестой элемент каждого mas[i]

    "23"   — правильно
    23     — ловушка

Сравнение в call() нестрогое (==), поэтому числовой ответ 4 и строковый код
"4" совпадут, и одиночный правильный ответ сработает. Ошибку заметить
трудно, но если правильный ответ начнётся с нуля, числовая запись сломается.
Методичка прямо требует строку — так и записано во всех заданиях.


6. МАССИВ ЗАДАНИЙ НАЧИНАЕТСЯ С ИНДЕКСА 1
   mas[1] ... mas[5], при этом mas[0] не существует

Сделано, чтобы номер задания ii совпадал с индексом массива. Побочный
эффект: mas.length на единицу больше числа заданий, и перебирать массив
циклом for of нельзя — первым придёт undefined. Поэтому число заданий
хранится отдельно в переменной nn, и её надо не забыть поменять, если
заданий станет больше. В Буславский7-02.html nn равно 10.


7. ВИДИМОСТЬ ФОРМ ПОСЛЕ ПЕРВОГО ЗАПУСКА УПРАВЛЯЕТСЯ ТОЛЬКО СКРИПТОМ
   Раздел style, правило #form2, #form3 { display: none; }

Скрипт проставляет display через атрибут style прямо в теге, а такое
значение сильнее правила из раздела style. После первого нажатия «Старт»
правило #form2 больше ни на что не влияет: видимостью целиком распоряжаются
функции start(), call() и over(). Вернуть исходное состояние можно кнопкой
«Завершить» или перезагрузкой.
