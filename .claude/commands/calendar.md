Синхронизируй Google Календарь со сценарием. Аргументы: `$ARGUMENTS`

## 1. Флаги

Переведи аргументы в флаги скрипта. Пусто — период берётся из сценария.

| Сказано | Флаг |
|---|---|
| `неделя`, `эта неделя` | `--week` |
| `неделя 2026-09-14` | `--week 2026-09-14` |
| `следующая неделя` | `--next-week` |
| `месяц`, `месяц 2026-10` | `--month` / `--month 2026-10` |
| `с 2026-09-01 по 2026-10-31` | `--from 2026-09-01 --to 2026-10-31` |
| `по дням`, `без повторов` | `--flat` |
| `из копии путь.json` | `--backup путь.json` |
| `проверить`, `посмотреть` | ничего не пишем, см. шаг 5 |
| `очистить`, `стереть` | план не строим, см. шаг 5 |

## 2. План

```
node scripts/calendar-plan.mjs --json <флаги>
```

Скрипт печатает `calendarId`, `timeZone`, `marker`, `period` и `events`.
Каждое событие уже готово к отправке: `summary`, `startTime`, `endTime`,
`timeZone`, `recurrenceData`, `colorId`, `location`, `overrideReminders`,
`description` с подписью `<marker> · <ключ> · v=<хэш>`.

Ошибка валидации — покажи её и остановись, в календарь не лезь.

## 3. Что уже стоит в календаре

`list_events` с `calendarId` из плана, `startTime` = `period.from` в 00:00,
`endTime` = день после `period.to`, `fullText` = `marker`, `pageSize` 250.
Пройди все страницы по `nextPageToken`.

Из каждого события вытащи ключ и хэш регуляркой `<marker> · (.+?) · v=(\w+)`.
Повторяющееся событие может вернуться пачкой копий с одинаковым ключом —
схлопни их: бери `recurringEventId`, если он есть, иначе `id`.

**Событие без подписи — чужое. Не трогай его ни при каких аргументах.**

## 4. Разница

| Состояние | Действие |
|---|---|
| ключ в плане, в календаре нет | `create_event` |
| ключ есть, хэши совпали | ничего |
| ключ есть, хэши разные | `delete_event`, затем `create_event` |
| ключ в календаре, в плане нет | `delete_event` |

Пересоздание вместо правки — потому что `update_event` не умеет менять
повторы, а именно они меняются, когда правишь звонки или каникулы.
Ставь `notificationLevel: "NONE"`: это личное расписание, письма не нужны.

Спроси через `AskUserQuestion` перед записью, если удалений больше десяти
или удалений больше, чем создаётся: похоже на сбитый период или чужой
календарь, лучше переспросить.

## 5. Особые режимы

**`проверить`** — покажи разницу таблицей и остановись. Ни одной записи.

**`очистить`** — план не строится: удали все события с подписью за период
(`period` возьми из `calendar/scenario.json` или из аргументов) и покажи,
сколько удалено. Перед удалением подтверди через `AskUserQuestion`.

## 6. Отчёт

Короткая таблица: создано, обновлено, удалено, без изменений — и одна
строка вроде «Расписание в календаре с 01.09 по 25.12, 24 события».
Ничего не изменилось — так и скажи одной строкой.
